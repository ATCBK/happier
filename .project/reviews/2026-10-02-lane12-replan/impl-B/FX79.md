## Observed cause and corrected owners

The shared review path is `ProjectGitSurface` → `WorkspaceScmReviewDetailsView` → `ChangedFilesReview` → `useChangedFilesReviewPrefetch` / `useChangedFilesReviewDiffLoading` → workspace/session unified-diff acquisition → `machineScmDiffFile` → machine RPC. Session review uses the same review/acquisition owners. The existing `ScmDiffCache.getOrLoad` already owns cross-consumer in-flight sharing and unchanged-result reuse; no additional cache was added.

Observed in current source:

- Workspace reviews have no Session id. The prefetch hook previously disabled their viewability observations, leaving their initial requested file list in use. Initial demand could contain the whole small review or the configured buffer. Viewability now works without a Session; initial demand is one anchor, then the viewport supplies paths. An observed viewport with no file rows returns an empty demand.
- The loader previously interpreted explicit `[]` as missing demand and fetched an anchor anyway. It now distinguishes missing demand from empty demand, including in its effect identity.
- `ChangedFilesReview` previously disabled the shared acquisition cache whenever prefetch was disabled, including Workspace reviews. It now always passes the existing cache. Its foreground demand respects expansion; large-review buffer rows no longer independently demand diffs. The retained scheduler only buffers expanded rows and delegates acquisition to the same cache. Search remains explicit demand for the complete review.
- The loader's elapsed-time check could re-request a validated snapshot on an unrelated render after 60 seconds. A real transport-boundary RED observed two RPCs instead of one. A snapshot now remains validated until the existing SCM snapshot/manual-refresh invalidation clears it. The canonical signature still includes `fetchedAt`: equal status/line counts are not assumed to mean equal file bytes.
- `useScmDiffSummaryBinding` restored saved results on comparison object identity despite already having the canonical `scmComparisonKey`. Three equivalent rerenders produced four real list RPCs while the first was pending. Its restore effect now uses the semantic key. The composed regression verifies one request while pending and settled, with fresh requests on source, checkout and Account changes.

Daemon path: SCM dispatch → current backend selection/detection → supplied backend context → `gitDiffFile` → plugin SDK command service → CLI SCM process runner. Current source already uses asynchronous `child_process.spawn`; no synchronous child-process API was found in the live SCM execution corridor. Native process creation still has synchronous setup, so the old profiler's spawn frames are not proof of a `spawnSync` call.

`detectGitRepo` now obtains inside-worktree and root facts from one `git rev-parse` invocation instead of two. Its real-Git test composes nested-directory detection with `gitDiffFile` and counts one repository probe. The diff operation already consumes the supplied detection; it does not redetect internally. Bare repositories, unavailable probes, ownership refusal and non-repositories retain their existing classifications.

No retained detection lifecycle exists at this route to justify a cross-request repository cache, so fresh backend selection remains. Status summaries contain status/statistics rather than the requested patch bytes. Existing provider/captured diffs continue to satisfy the UI loader without a machine diff RPC. The per-file API accepts one path; no new batching protocol or parallel reader was introduced.
