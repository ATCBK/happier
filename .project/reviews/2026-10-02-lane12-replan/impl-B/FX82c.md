## Source deliverables

Paths are relative to the repository root; these describe this lane's hunks, not ownership of every existing edit in those files.

- `packages/protocol/src/crypto/boxPublicKeyValidation.ts`: the one public-key validator retains its unchanged X25519 probe result by the complete public-key bytes. Separate arrays with identical bytes reuse validation; mutating an array changes its identity. Both accepted and refused identities retain the same admission outcome. This process-lifetime map contains only public bytes and booleans, and has no arbitrary size or expiry cutoff. `boxBundle.ts` sealing, sender validation during opening, and schema callers still use that validator.
- `apps/ui/sources/sync/encryption/encryption.ts`: extends the existing scoped `dataKeyOpenings` owner to retain successful pure opens rather than deleting every completed result. There is no second decrypt map, cross-instance key registry, timer, poll or retry budget. Returned keys are copied. Account/Home/generation fences and recipient-byte currentness are checked before reuse/publication; generation advancement and changed recipient material retire retention. Failed opens remain retryable and unretained. A signal-bearing native request keeps its independent in-flight cancellation custody, deduplicates its own identical inputs, and may reuse completed results. Separate cancellable in-flight requests can still each open a shared miss; no new cancellation/refcount machinery was introduced to promise global exactly-once execution.
- `apps/ui/sources/sync/engine/sessions/sessionSnapshot.ts`: chooses required, route, visible, active, priority/report and eager rows from the complete current page **before** `needsWarmHydration` removes completed work. An unchanged refresh therefore does not promote the next historical eager slice. Unopened rows outside that existing caller policy do not open a DEK. Already retained row keys still reconcile envelope/mode changes; explicit demand subsequently opens a deferred row through the same path. Existing primary-Home pin inputs, viewport inputs, concurrent-Home policy, explicit query-page consumption, exact-Session reads, retirement fences and owner-metadata projection hunks remain in place.
- Existing tests updated: `packages/protocol/src/crypto/boxBundle.test.ts`, `apps/ui/sources/sync/encryption/encryption.nativeDataKeyEnvelopeContract.test.ts`, and `apps/ui/sources/sync/engine/sessions/sessionSnapshot.performance.test.ts`.

Split-brain check: Protocol still owns public-key admission; `Encryption` still owns pure envelope opening and native routing. Session DEK/envelope maps and Artifact row-key maps retain their existing row-custody purposes and delegate opening to that owner. Separate Action invocations intentionally retain separate Encryption instances; this change does not share keys between invocations or grant cached row access. Account-mode/content refusal and keyless/E2EE fail-closed decisions were not replaced. Reuse is scoped to the current Encryption identity and generation, not a global promise across Accounts, Homes, replacement keys or independent invocation lifetimes.

Visible changes: no new controls, copy, components or styles. The UI-craft skill did not require a new design composition. Existing rendered Home and Session-list surfaces were used for measurement. Documentation remains unchanged because wire/persistence formats, crypto admission, mode authority and published UI flows are unchanged; this is development execution/retention work, not a release availability claim.
