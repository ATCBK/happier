**Observed current behavior:** the existing real-Home table at `externalActionExecutionAuthorization.sqlite.integration.spec.ts:1325` creates a status-only PAT restricted to the bound Machine. **Observed causal falsifier:** memory-only run `12329` restored only the old schema-valid status read/list allowance inside the canonical server predicate. The direct-PAT 403 and successful root issuance assertions still passed. This reproduces SR6's exploit conditions and demonstrates that the refusal regression discriminates the pre-FX120 row allowance.

An earlier broader in-memory reversal (`16083`) restored the generic status branch and removed the finite/inspection row restriction. All five affected roots failed their row-refusal assertions with 200/private rows. That broad reversal additionally reopened status trust read, so it is not presented as an exact reconstruction of all historical behavior. The narrower status-only reversal above isolates SR6-1 without that extra change. A helper print labeled `FAILED_TESTS 1` in the broad run counted a top-level suite; the authoritative Vitest result is **five failed tests**, not one.

**Derived conclusion:** SR6-1 is closed because the formerly exploitable Home route now refuses the unchanged root/signature and becomes exploitable again when only its row-purpose allowance is restored. Account-wide row storage remains intentionally Account-scoped; the fix removes inappropriate execution-root authority rather than pretending the list schema scopes rows to a Project.
