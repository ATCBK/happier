Connect MCP servers to give your Agents external tools, such as documentation lookup, browser automation and internal APIs. Save a server in your Account, set **Where it's on**, then choose what each Session receives.

## Availability

This guide describes **unreleased 0.3 development behavior**. The replacement MCP collection, sign-in flow and Session integration are still being validated. Per-tool enforcement depends on the Agent's proven integration, and production OAuth callback deployment remains a release check.

## Before you begin

Use the same Happier Account on your client and connected machines. A reachable machine is needed to test a server, start its local command or complete MCP sign-in. Install any prerequisites the server requires on the machine that will run it.

Review the server's identity and requested access before connecting it. Local servers execute on your machine; remote servers receive the tool calls and data you send them. [Permissions](/sessions/permissions) governs the Session's broader access.

## Add a server

Open **Settings → MCP servers**, then use **+**. The development add flow offers registry browsing, **Paste a config**, and manual configuration. Open an item's details to review what will be added, provide required values, choose **Where it's on**, and add it.

Manual configuration supports a **Local command** (`stdio`), **Remote HTTP** (Streamable HTTP), or **Remote SSE**. A local command has arguments, environment values and an optional working directory. Remote configuration has a URL and optional headers. Per-machine differences can override configuration without changing which places enable the server.

To adjust a copy, choose **Duplicate** from a saved server's menu. Happier opens the new server with a unique name and the same configuration. Its reach starts at Everywhere, and an OAuth server needs its own sign-in.

### Paste a config

Paste a supported host JSON snippet or install link. Happier parses the definitions and asks you to supply values such as API keys and environment variables before adding them. Imported definitions use the same catalog and controls as a manually added server.

For example:

```json
{
  "mcpServers": {
    "docs": {
      "url": "https://mcp.example.com"
    }
  }
}
```

A bare `url` defaults to **Streamable HTTP**. An explicit `type: "sse"` or `transport: "sse"` selects SSE; a Gemini-style configuration using `httpUrl` for HTTP can identify its `url` entries as SSE. Review the prefilled transport choice and change it before adding when needed. The server detail retains the transport control. Happier does not guess transport from the URL or probe it during parsing.

Resolve each imported value to a Saved Secret, a machine environment reference or a nonsensitive literal. Importing does not silently discard credentials. Review any unsupported-field warnings and the resulting server definition.

### Found on your machines

The **Found on your machines** view reads definitions from Agent-native configuration on the selected machine and directory. Detection is read-only; add a definition to make it Happier-managed. Discovery does not prove an Agent loads it in a Happier Session. In particular, Codex's native definitions are not included as loaded native servers in Happier-session preview.

Sources belong to their declaring Agent, including plugin-contributed Agents. An unavailable scan reports its failure; offline last-known information is dated. Bring the machine online to retrieve current configuration.

## Where it's on

Use the server's **Where it's on** control for Everywhere, Agent exceptions, machine rules or Account Project rules. New additions by you default to Everywhere. A Project rule follows that Project across its machines. A local command still needs its executable, files and values on each target machine.

Agent exceptions apply across places unless a rule for that same Agent overrides them. These rules choose defaults. A Session can explicitly include an existing server even when its rules say Off or name another machine or Agent. Unsupported delivery, missing configuration or an unreachable machine still produce a visible refusal.

Servers declared by a plugin use the same reach rules and Session selection. The built-in **happier** tool server keeps its own [Actions settings](/extending/happier-tools).

## Sign in to a remote server

For a server configured for OAuth, choose **Sign in** on its detail. Happier starts an Account-owned attempt through a connected daemon. Complete authorization in the browser, use the phone handoff, or paste the **full callback URL** into the fallback form, including its `state` and any `iss` value.

The stable client metadata URL is
`https://app.happier.dev/oauth/mcp/client-metadata.json`, and its callback is
`https://app.happier.dev/oauth/mcp/callback`. The callback page returns the result to the initiating app flow where supported. Self-hosted web openers use the paste fallback. Publishing these endpoints and verifying installed-app return on devices are release checks; their development source does not imply they are deployed.

Sign-in requires HTTPS for the resource and its authorization discovery, registration, browser and token endpoints, including localhost. Happier requires PKCE S256 and uses client metadata when the service supports it, otherwise a saved app registration or dynamic registration. Pasting a callback completes an existing attempt, rather than bypassing registration.

The grant belongs to your Account's Connected Accounts, not a separate machine token store. Storage follows the [Account encryption mode](/security/encryption). A scope challenge shows **Needs more access**; reconnect explicitly to approve the combined scopes. Signing out asks for confirmation. Another origin cannot complete the attempt, and an issuer mismatch is refused before token exchange.

For SSE, an advertised message endpoint may use another path on the initial server's origin. An endpoint on another origin is refused; the token remains bound to the original resource.

### Use your own OAuth app

If automatic registration is refused, choose **Use your own OAuth app** in the sign-in section. Create an OAuth app in the service's console and register the callback URL shown in Happier: `https://app.happier.dev/oauth/mcp/callback`. Enter its **Client ID** and, for a confidential app, its optional **Client secret**, then choose **Sign in**.

The app registration stays with this server's Account-held sign-in configuration and follows the [Account encryption mode](/security/encryption). Your other machines reuse it. A service that accepts Happier's client metadata identity continues to use that identity; the sign-in section explains that your app is not needed. If the app is rejected, check its details and registered callback URL, then edit it and retry. **Edit your OAuth app** also lets you replace it or remove the server's saved registrations and retry automatic sign-in. The API-key alternative remains available where offered.

Agents use the same `mcp.servers.signIn.start` Action with `client: { clientId, clientSecret? }`; `client: null` removes the saved registrations for that server. The CLI accepts `--client-id` and optional `--client-secret` on `happier mcp servers sign-in <name>`, or `--remove-client` to retry automatic sign-in. Keep client secrets out of shared command output and shell history.

### API keys and other values

Use a **Saved Secret** for a reusable API key or token. Remote headers can use a template such as `Bearer {api_key}` bound to that secret. A machine environment reference reads the value on the target machine. Prefer literals for nonsensitive values.

Happier's managed credential paths avoid exposing secret values in Agent argv, ambient tool-shell environment, logs or transcript events. Agent-specific private files or the host bridge deliver them where needed and retire them with their owning operation or Session. This is not isolation from another process running as the same OS user: that user can read accessible credential files and process state.

## Tools: Off, Ask and Allow

Use **Test** to obtain the server's tool list, then open **Tools**. The server default is **Ask**, **Allow read-only** or **Allow all**; each tool can follow that default or have an explicit setting.

| Setting | Effect where the Agent supports enforcement |
| --- | --- |
| **Off** | Hide the tool at launch, or reject its call through the live approval handler. |
| **Ask** | Use the Session's permission decision; full-access mode may allow it automatically. |
| **Allow** | Permit the MCP tool without that additional MCP approval. Other Session restrictions still apply. |

Read/write/destructive annotations help describe tools and inform defaults; they are claims from the server, not an independent safety audit. Read-only automatic permission also requires the server's explicit read-only opt-in.

The detail names Agents where **Tool settings don't apply to &lt;Agent&gt;**. Happier uses an Agent's native controls or its validated live approval path; there is no permission proxy for unsupported Agents. When Off hides a tool from the Agent at launch, turning it back on requires the later launch stated by the page. A blocked-at-call tool can remain visible while its calls are refused.

**Always allow** on an eligible tool approval writes this same tool setting. A failed save does not mean a persistent policy was installed. Built-in Happier tools keep their separate Actions policy.

## Test and diagnose a server

Testing resolves configuration and values, starts or connects to the server, and reads its tool inventory. Development remote tests read every tool page and retain the server's identity, version and instructions. The detail reports current machine results and dates any last-known state.

If Test fails, check the executable and working directory for a local server, the URL and chosen transport for a remote server, its sign-in or Saved Secret bindings, and the target machine's environment. Testing from one machine does not establish readiness on another.

**Strict mode**, under **Settings → Sessions**, refuses startup when an enabled effective server cannot be resolved or started. With strict mode Off, optional server failures can let the Session continue with healthy servers and a visible capability notice. Read that notice before assuming all tools are available.

## Choose servers for a Session

The development **This session gets** sheet separates MCP servers from Skills. Include, exclude or reset a server for this Session without rewriting saved defaults. Preview reports the selected Agent, machine and directory's effective servers; Agent-native definitions contribute only when that Agent actually loads them in Happier.

An MCP selection change in a running Session normally applies at the next settled turn through restart with resume. A terminal-started Session or a visible Windows console shows **Restart to apply**, with a restart control or a terminal hint. A path without resume support shows **Applies to new sessions**. Saved selection and acknowledged application are separate states; follow the sheet's status.

Editing a definition changes later server materialization; it does not promise arbitrary hot swapping inside an already-running Agent.

## Ask an Agent or use the CLI

The catalog, rules, sign-in and tool controls use the same [host Actions](/plugins/api/host-actions) across the app, CLI, Agent and MCP surfaces. Agent and CLI writes ask by default; configure those policies under **Settings → Actions**. Your own reversible control changes apply directly; deletion and sign-out confirm.

```bash
happier mcp servers list
happier mcp servers duplicate docs
happier mcp servers add docs --transport http --url https://mcp.example.com
happier mcp servers test docs --machine <machine-id>
happier mcp servers sign-in docs
happier mcp servers tools docs
happier mcp found --machine <machine-id> --provider codex
```

Use `happier mcp servers --help` and subcommand help for current arguments and the generated [host Action catalog](/plugins/api/host-actions) for the complete schema reference.
