title: Artifacts
description: Keep reusable documents from your sessions together, revisit earlier versions, and share them with other Accounts.

Keep the useful output of a session after the conversation moves on. Artifacts
are saved in your Account, so a document can sit alongside the prompts, Boards,
Workflows, Roles and launch profiles you reuse.

## Availability

This guide describes the **0.3 development version**, not a shipped release.
The browser and history described here require a Home running the current 0.3
Artifacts implementation and schema. Private HTML previews additionally require
the Home's isolated HTTPS preview host. Public links can use the Home's HTTPS
hostname only when its owner enables the option described below. This is
development-only behavior, not released availability.

## Browse and open

Open **Artifacts** in the app navigation. Search matches titles; **Kind** narrows
the collection, and **Sort** orders it by recently updated, recently created or
title. Choose **Grid** for previews or **List** for a compact view. Happier
remembers that choice on the device.

On a wide screen, a document opens beside the collection. On a phone, it opens
as its own page. Prompts, Boards, Workflows, Roles and launch profiles open in
their own surfaces, where their editing and use controls belong.

HTML documents show a static card in the grid. Opening one loads its interactive
preview on the isolated host, not inside the app's document origin. If the host
or content is unavailable, the preview offers **Retry**. It does not make the
document public.

In current 0.3 development source, agents create or publish HTML through the
existing Artifact Actions using `ArtifactHtmlBundleV1`: an entrypoint and a map
of relative files, each with a MIME type and base64 bytes. A one-file document
uses the same bundle. Workspace file or directory acquisition uses the existing
publication path, with confinement and symlink refusal; it is not a preview
server. Private preview links carry access secrets, not the document bytes.

The shared document owner resolves local HTML/CSS assets, classic scripts,
modules and import maps, and runtime reads of declared bundle files. External
fetches and assets require an admitted network policy; a bundle alone grants
none. The opaque sandbox cannot use the app's cookies, storage or authenticated
API. Caller-authored Actions and Resources, when available in a private mounted
surface, still use the current viewer's ordinary authority on every request.
See [HTML network and approval](/sessions/permissions#agent-html-network-in-development).

Copying a Session visual into an Artifact creates independent saved content;
later edits to either original do not update the other. It uses normal Artifact
access and approval, not the source Session's audience or creator authority.

In 0.3 development source, saving a typed Session visual makes a reusable widget
definition. This includes native built-in widgets: the copy keeps its declared
inputs, bindings and policy, and reads live data with the destination viewer's
authority. Sharing that definition with an Account does not grant access to
its data sources. Anonymous public links show an unavailable state for built-ins,
installed widgets and other live Resource-backed definitions that need a Happier
viewer connection. They never use the author's credentials or silently display
a frozen snapshot. Static declarative visuals and HTML bundles can render in
the public viewer under their saved policy.

## Organize with folders

In 0.3 development, all library Artifacts share one personal folder tree:
documents, prompts, memory, Boards, widgets, Workflows, Roles and launch profiles.
The Prompt Library is a filtered view of that same tree. Moving a prompt there
also changes where it appears in Artifacts.

Use **Move to folder** to choose a destination, or drag an Artifact onto a
folder. Folders can nest inside other folders. Your placement belongs to your
Account: moving a shared Artifact does not change its content, sharing or
another person's folders. Deleting a folder keeps its Artifacts.

## Save a document

Choose **New document**, enter a title and content, then **Save**. Use **Edit**
on the document to change it later. If you cancel with unsaved changes, Happier
asks before discarding them.

## Passage comments and proposed edits in development

The unreleased 0.3 Actions can discuss prose Docs through a
[Home Discussion](/accounts/session-sharing#home-discussions-03-development).
They require current Doc access; posting also checks the Discussion's access
and whether its audience may receive the passage. The Conversations feature
must be enabled for comments and proposals. The page's passage-selection and
review flow is still being built; these are Action contracts, not screen instructions.

Use `doc.read` to read the current text and revision, `doc.comment.reply` to
comment or reply, and `doc.edit.propose` to save a proposed change with its
original passage, before/after text and reason. A proposal changes no Doc text.
Quotes and proposals stay in the Discussion content; a link grants no access.

Only a present person with current Discussion access and Doc edit permission
can use `doc.edit.accept` or `doc.edit.decline`. Accept checks the complete
reviewed revision. If the Doc changed, nothing is applied: read it again and
ask for a fresh proposal. Decline leaves the Doc unchanged. Waiving an Action
confirmation never lets an Agent accept. Ordinary Doc editing remains available.

## Revisit an earlier version

Open **History** on a document, choose an earlier version, and preview its
content. **Restore version** saves that content as a new version; it does not
overwrite the current version in place. The history sheet shows how many
versions the Home retains.

History is bounded, not a permanent archive. A Home's operator can configure
retention with `HAPPIER_ARTIFACT_REVISION_RETENTION_COUNT`, so an older version
may no longer be available. A failed history read offers **Retry** rather than
treating the failure as an empty history.

## Share access

Choose **Share** to manage access through the existing Account and Team sharing
surface. Documents and Boards use **Can read**; reusable kinds use **Can use**.
**Can edit** allows changes to the shared original, while **Admin** includes
managing its shares. Available operations still depend on your access to that
artifact.

A copied app link points at the artifact; it does not grant access by itself.
The recipient must already have access. Granting Account or Team access does
not make the artifact public. See [Sharing and Teams](/accounts/session-sharing) for
the surrounding Account and Team model.

Public links disclose stored content to anyone who has the link. In the
**unreleased 0.3 development version**, an isolated share domain is preferred.
When it is unavailable, the Home owner can enable **Allow public links on this
hostname** in **Home administration → Reach**. This default-off setting needs a
configured HTTPS public address and a working public-link rate limiter. Public
HTML uses the same restricted opaque sandbox on either host; it receives no
Account credentials or authenticated app bridge. PDFs are download-only on the
Home's hostname and can preview inline on an isolated share host. The setting
does not make private HTML previews available on the main hostname or change
which Artifact kinds may be published. See the
[public-link hosting prerequisites](/self-hosting/local-service-previews#stored-content-public-links-in-03-development).

Before sharing network-enabled HTML, review the disclosure: it can send visible
content elsewhere, reveal the viewer's IP address and load changing remote code
or assets. The development sharing flow offers sharing with network off. For an
Artifact link, this saves a no-network policy on the Artifact before creating
the link, so private previews of that saved copy also use the narrowed policy.
If the Artifact was copied from a Session visual, the source visual is unchanged.
For a public Session share, network off applies only to viewers of that share
and leaves the Session visuals unchanged. Public viewers never receive
authenticated Actions or Resources.

If the policy save succeeds but link creation fails, the saved Artifact keeps
the no-network policy. Retry link creation from its **Share** controls; you do
not need to save another copy. If saving the policy requires approval, link
creation cannot proceed until that save succeeds.

## Storage and failed saves

When the operator sets an Account storage budget, the browser shows usage and
the limit. Retained versions count toward storage too. Without a configured
Account limit, the meter is hidden; a missing usage read is not proof that
storage is unlimited.

A Home can also set a per-document budget. A save that exceeds either budget
shows the size and limit and keeps your edits in the editor. For an Account
budget, remove artifacts you no longer need before retrying; for a document
budget, reduce the content. Do not leave the editor until the save succeeds or
you have copied the unsaved content somewhere safe.

Operators configure the Account budget with
`HAPPIER_ARTIFACT_ACCOUNT_LIMIT_BYTES` and the document budget with
`HAPPIER_ARTIFACT_DOCUMENT_LIMIT_BYTES`. See the
[server environment reference](/self-hosting/env) for deployment configuration.
