---
title: MCP in agent runtime plugins
description: Use MCP servers and discovery contributions from plugin and agent runtime code.
---

MCP support is split between static manifest descriptors and runtime registration.

## Manifest descriptors

Declare MCP servers and discovery contributions in the manifest when they should be projected or discovered before executable plugin code runs.

## Code-defined runtime binding

Bind executable MCP behavior through `definePlugin(...)`:

- `mcp.servers.<id>.runtime` for a dynamic MCP server
- `mcp.discoverySources.<id>.discover` for a discovery contribution

Runtime-discovered per-session servers should be returned through the MCP runtime/discovery APIs, not promoted into the static plugin catalog by side effect.

## Declaring which agent a discovery source belongs to

A discovery source must declare its owning agent as `metadata.agentId` on the
contribution declaration. Detection uses that declared id — bundled and
externally contributed agent ids alike — and never infers one from the
contribution's local id. A source without it is reported as an `unsupported`
detection warning and contributes no servers.

```ts
mcp: {
  discoverySources: {
    config: {
      declaration: { title: 'Acme MCP configuration', metadata: { agentId: 'acme.cli' } },
      discover: async (input) => ({ items: [], endpoints: [], warnings: [] }),
    },
  },
}
```

This one declaration is also what puts the agent on the MCP settings screen's
detected-servers tab. Happier derives the scan offer from the discovery source
the agent owns, so there is nothing else to declare — and no way for the screen
to offer a scan that has no source behind it. Bundled and externally contributed
agents reach the screen the same way.

## Session-scoped MCP

In 0.3 development, the host resolves reach defaults and Session overrides once
and supplies the effective `mcpServers` through `AgentSessionOpenRequest` (or the
Run open request). `context.session.services.mcp.resolveServers(...)` remains a
projection of that applied set, rather than an independent catalog resolver.
An explicit Session include can override Off or other-place defaults; declared
Agent support and materialization still constrain delivery. The host owns
integration and transport exposure.

`mcpToolPolicy` travels beside those servers. Declare `mcpToolControl` and
`mcpToolLoading` only for behavior proven by the Agent's real launch and permission
path. The host's single decision owner feeds native controls and the live
approval handler. Missing support stays unsupported, and the server detail says
**Tool settings don't apply to &lt;Agent&gt;**. Off may hide a tool at launch or block
its calls; a hidden tool returning requires the later launch named by the UI.
Plugin-declared MCP servers use the same reach owner and appear with their
supplying plugin, while configuration and removal remain declaration-owned.

## Agent rule

In 0.3 development, remote MCP OAuth sign-in is host-owned. Agent plugins
receive the host's stdio bridge configuration, not its OAuth tokens or client
registration secrets. The bridge obtains a current bearer for each request
through the existing Connected Accounts broker. Plugins do not register the
reserved MCP sign-in service or implement a parallel token store.

The host client metadata is
`https://app.happier.dev/oauth/mcp/client-metadata.json`; the callback is
`https://app.happier.dev/oauth/mcp/callback`. Client metadata registration precedes
dynamic client registration. Completion validates full state and any required
issuer before exchange. Endpoint publication and installed-app return are
release checks. Self-hosted openers use the full-URL paste fallback.

Private launch/bridge files keep resolved credentials out of Agent argv and the
ambient tool-shell environment. Their operation or Session lifetime owns
cleanup. This protects delivery from ambient disclosure; another process
running as the same OS user can still read accessible credential files.

For SSE in 0.3 development, the bridge accepts an advertised message endpoint
on the initial server's origin and refuses other origins. The OAuth grant
remains bound to the exact initial resource. Remote discovery follows every
tool page and preserves the upstream server's identity, version and instructions.

Kilo's development ACP integration cancels MCP calls whose native names lose
their raw identity, including dotted or underscore tool names. It also refuses
ambiguous server aliases. Built-in Happier tools retain their Action handling.

Agent-specific MCP configuration belongs in the agent leaf or manifest descriptors. Shared runtime code should not branch on `agentId` to discover MCP servers.
