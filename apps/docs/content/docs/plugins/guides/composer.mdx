> **Developer Preview:** the generated [capability matrix](/plugins/manifest/availability)
> marks all four `composer.*` contribution families available in current source
> because their producer, public projection, and applicable host lifecycle are
> implemented. Maintained-consumer, loaded-platform, and release evidence are
> separate fields; none determines source availability. The
> mounted read path (`useComposer` / `useComposerView`) is ordinary
> `@happier-dev/plugin-ui` API, and the SDK remains unpublished.

The Composer is the message draft a person is writing. A plugin touches it in
two places, and they are deliberately different:

| You want to… | Use |
| --- | --- |
| Add something the person can insert or attach | `composer` in `definePlugin(...)` |
| Read or change the draft from your own mounted surface | `useComposer()` / `useComposerView()` |

The host owns the draft, its revision, and its lifecycle. A plugin never keeps a
second copy of the draft, a shared draft store, or its own submit path.

## Declare what the Composer offers

`composer` is one author namespace with four families. Declare only the ones the
feature needs; each entry's key is its local id.

- **`references`** — searchable candidates the person inserts inline (`@`-style).
- **`attachments`** — structured values the draft carries alongside its text.
- **`controls`** — the affordances shown in the Composer toolbar.
- **`regions`** — a surface mounted directly before or after the Composer.

A control is the affordance; an attachment is what the draft ends up holding.
They are separate local ids on purpose.

In 0.3 development builds, a control can request an initial toolbar placement
with `defaultPlacement: 'pinned'`. Omit it, or use `'overflow'`, for the + menu.
This is a default, not a visibility guarantee: the person's device-local
placement preference takes precedence. Actions keep their existing
`composer.primary` and `composer.more` bindings; an Action with both appears
only once, initially pinned. Controls and Actions with the same local id keep
separate placement preferences. The optional Control field requires the
matching development host and SDK; older strict manifest readers do not accept
it.

```ts
import {
  defineComposerAttachment,
  defineComposerControl,
  defineComposerReference,
  defineComposerRegion,
  definePlugin,
  defineUiSurfaceDefinition,
} from '@happier-dev/plugin-sdk';
import { defineProtocolObject, defineProtocolString } from '@happier-dev/plugin-sdk/protocol';

// Composer slots use a renderer-only surface: it has no destination or view.
// `defineUiSurfaceDefinition` derives the renderer id as `<surfaceId>-renderer`.
const ticketComposer = defineUiSurfaceDefinition({
  id: 'ticket-composer',
  placement: 'rendererOnly',
  renderer: {
    kind: 'reactNative',
    requiredHostMethods: [
      'context',
      'readComposer',
      'watchComposer',
      'applyComposer',
      'pickComposerMedia',
      'inspectComposerContent',
      'releaseComposerContent',
    ],
  },
});

export const { manifest, activate } = definePlugin({
  id: 'com.example.tickets',
  version: '0.1.0',
  entrypoints: { daemon: './dist/index.js' },
  composer: {
    references: {
      tickets: defineComposerReference({
        title: 'Tickets',
        icon: 'search',
        async search(query, context) {
          const found = await findTickets(query, context.signal);
          return found.map((ticket) => ({ id: ticket.id, label: ticket.title }));
        },
        async resolve(candidateId, context) {
          const [ticket] = await findTickets(candidateId, context.signal);
          return {
            id: candidateId,
            label: ticket?.title ?? candidateId,
            // The text the model actually receives for this reference.
            context: `Ticket ${candidateId}: ${ticket?.title ?? 'unknown'}`,
          };
        },
      }),
    },
    attachments: {
      ticket: defineComposerAttachment({
        title: 'Ticket',
        icon: 'file',
        cardinality: 'many',
        picker: 'ticket-composer-renderer',
        display: {
          kind: 'surface',
          renderer: 'ticket-composer-renderer',
          sizing: 'compact',
        },
        preview: {
          kind: 'surface',
          renderer: 'ticket-composer-renderer',
          presentation: 'popover',
        },
        // The draft carries identity only. Publish the schema once so the
        // attachment and whatever reads it cannot disagree about its shape.
        value: defineProtocolObject({
          ticketId: defineProtocolString(),
        }, { policy: 'closed' }),
      }),
    },
    controls: {
      'add-ticket': defineComposerControl({
        label: 'Attach ticket',
        icon: 'file',
        defaultPlacement: 'pinned',
        // Omitting `scopes` is the widest policy, not none. Name the scopes
        // whose messages can actually hold this attachment.
        scopes: ['session', 'newSession', 'pendingMessage'],
        interaction: {
          kind: 'attachmentPicker',
          attachment: 'ticket',
          presentation: 'popover',
          layout: 'list',
        },
      }),
    },
    regions: {
      'ticket-context': defineComposerRegion({
        placement: 'afterComposer',
        renderer: 'ticket-composer-renderer',
      }),
    },
  },
  ui: { surfaces: [ticketComposer] },
});

async function findTickets(
  query: string,
  signal: AbortSignal,
): Promise<readonly Readonly<{ id: string; title: string }>[]> {
  signal.throwIfAborted();
  return [{ id: 'T-1', title: `Ticket matching ${query}` }];
}
```

The surface id derives the executable artifact id
`ticket-composer-renderer`. Export its `renderSurface` module from
`./happier-plugin-ui/ticket-composer-renderer`; there is no platform matrix or
author-owned bundler configuration.

`search` and `resolve` receive the host's `AbortSignal`. Honour it: the person
keeps typing and the host retires the previous query.

### Inline reference chips (0.3 development)

In unreleased 0.3 source, selecting a contributed reference inserts an atomic
chip at the caret. A drop inserts it at the drop caret; **Mention in composer**
uses the same insertion owner. The host stores an inline token in the text and
its identity in the existing typed reference record. Pasting token-shaped text
does not create a reference. Let the host build and position the reference;
plain text alone supplies no binding.

Sent messages draw bound references inline. The Agent receives a readable
marker at that position and the resolved context in one reference block.
Repeated mentions reuse the same context entry. The resolver still owns
send-time context; a chip label is display text, not authority or stored context.

## Read the mounted draft

From a mounted surface, `useComposer()` returns the Composer facade and
`useComposerView(handle)` reads and observes one exact handle. The hook owns
React lifecycle only — the snapshot, its revision, availability, and
subscription disposal stay with the host.

```tsx
import * as React from 'react';
import { Button, Text, useComposer, useComposerView } from '@happier-dev/plugin-ui';

export function TicketContext() {
  const composers = useComposer();
  const composer = composers.current();
  const view = useComposerView(composer);

  if (view.pending === 'initial') return <Text variant="body" value="Loading draft…" />;
  if (view.error) return <Text variant="body" value={view.error.message} />;
  if (view.result?.status !== 'ready') return null;

  const { revision, capabilities } = view.result.snapshot;

  return (
    <Button
      title="Attach this ticket"
      disabled={!capabilities.attachments || composer === null}
      onPress={() => {
        void composer?.apply({
          expectedRevision: revision,
          operations: [{
            kind: 'attachment.add',
            attachmentLocalId: 'ticket',
            value: {
              key: 'ticket:T-1',
              value: { ticketId: 'T-1' },
              presentation: { label: 'Ticket T-1' },
            },
          }],
        });
      }}
    />
  );
}
```

`current()` is non-null only when the host supplied a Composer surface input to
this mount. `active()` and an exact `get(ref)` remain available on generic
mounts. Always pass the `expectedRevision` you read: the host rejects an apply
built on a stale draft instead of silently overwriting the person's edits.

### Attach and mention in one transaction

In unreleased 0.3, `attachment.add` accepts an optional `mentionAt` range in
the snapshot's text offsets. The host mints the attachment instance identity,
then replaces that range with a bound chip in the same transaction. Use a
collapsed range at the caret to insert without replacing text:

```ts
const read = await composer.read();
if (read.status === 'ready') {
  const snapshot = read.snapshot;
  const caret = snapshot.selection?.end ?? snapshot.text.length;
  await composer.apply({
    expectedRevision: snapshot.revision,
    operations: [{
      kind: 'attachment.add',
      attachmentLocalId: 'ticket',
      value: {
        key: 'ticket:T-1',
        value: { ticketId: 'T-1' },
        presentation: { label: 'Ticket T-1' },
      },
      mentionAt: { start: caret, end: caret },
    }],
  });
}
```

Without `mentionAt`, adding the attachment keeps it in the tray without
inserting a chip. Deleting a chip keeps its attachment; removing the attachment
also removes its chips. Offsets refer to the token-bearing snapshot text, not
to the shorter displayed chip labels; never choose an offset inside a reference.

### Decorations in the input

The mounted handle's `setDecorations(key, { revision, ranges })` applies treatments
to ranges of that same snapshot text. In unreleased 0.3, web and native inputs
draw them in place. Treatments are `highlight`, `muted`, `warning`, `success`,
`code`, or `{ kind: 'link', url }`; an optional `label` describes the range for
assistive technology. Decorations do not insert references or change draft
text. The host rejects stale revisions. Pass `null` to `setDecorations(key, null)`
to clear that decoration set.

## Discussion integration (development)

First-class Home Discussions are an unreleased 0.3 integration. Their composer
scope is `{ kind: 'discussion', discussionId }` through the same public reference,
mounted read/apply contract and host lifecycle. It identifies the Discussion under the host's
captured Home connection; the optional source Session is not its composer
identity. Treat an unsupported scope or unavailable mounted handle as
unavailable, and use the host's advertised methods and snapshot capabilities.
The SDK negotiates Discussion support through the callable
`readDiscussionComposer` method; `composer.read()` uses it automatically for a
Discussion reference. Older hosts return `unsupported_method` without sending
an unknown scope to their existing Session operations.

A structured participant mention carries the selected Account or Session
identity; display text such as `@Reviewer` does not select an executable
participant. Applying a draft edit is separate from posting it. Publication
uses the same admitted `discussion.*` Actions as the product, with current
grants, source-disclosure checks and any protected question cutoff. A plugin
cannot choose Agent provenance, bypass a pending approval or keep writing
through a retired mount.

The external-plugin Discussion fixture and loaded-runtime journey are still
being validated. Existing Composer contribution availability does not certify
this additional scope. See the [host Action
reference](/plugins/api/host-actions) for the generated operation inventory.

For development Discussion and Doc threads, import `ThreadMessage` and
`ReplyQuote` from `@happier-dev/plugin-ui/components`. Core uses the same
presentation owners. A quote's `source` is either `available` with admitted
text and optional navigation, or `unavailable` with a safe reason and no text
or navigation. These components do not read a source, grant access or turn a
displayed Task reference into a Discussion reply target; the caller retains
those decisions.

The development `ExecutableParticipantPicker` component from the same public
entrypoint renders the host's shared searchable choice list. Supply admitted
display sections, a controlled single or multiple selection, `canConfirm`,
labels and callbacks. Keep participant inventory, readiness, native model
setup and committing the selection in your controller; the component does
not discover or launch agents. Confirmation can be enabled for a configured
model even when no Session row is marked. Native and same-realm React Native
Web surfaces use the same presenter as core; a host without that presenter
shows an explicit unavailable message rather than a different picker.

## Staged media

`composer.content.pickMedia(...)` returns an opaque staged handle. Pass it
unchanged into the attachment operation, and release it if the apply does not
land. Authors never supply a transfer id, digest, path, or execution target.

```ts
import type { ComposerHandle } from '@happier-dev/plugin-ui';

export async function attachTicketEvidence(composer: ComposerHandle, ticketId: string) {
  const handle = await composer.content.pickMedia({
    attachmentLocalId: 'ticket',
    kinds: ['image'],
  });
  let attached = false;
  try {
    const read = await composer.read();
    if (read.status !== 'ready') return read;
    const result = await composer.apply({
      expectedRevision: read.snapshot.revision,
      operations: [{
        kind: 'attachment.add',
        attachmentLocalId: 'ticket',
        value: {
          key: `evidence:${ticketId}`,
          value: { ticketId },
          presentation: { label: `Evidence for ${ticketId}` },
        },
        content: { kind: 'stagedMedia', handle },
      }],
    });
    attached = result.status === 'applied';
    return result;
  } finally {
    if (!attached) await composer.content.release(handle);
  }
}
```

## Boundaries

- The host owns the draft, its revision, submission, and Message admission.
  There is no plugin-owned shared-draft state and no second submit path.
- A control's `interaction` is a declaration, not a callback registry. It names
  an Action, a `composerApply` operation set, a surface, or a destination.
- Renderers named by an attachment picker or a region are your own declared UI
  renderers; see [React Native UI](/plugins/ui/react-native).
- Opening the OS file picker inside a standalone third-party embed is an explicit
  Action-parity exclusion. Local file selection remains a human UI interaction;
  agents attach files through the existing attachment Actions instead. The
  connected-app channel does not target that frame's picker. See
  [embedded attachments](/extending/embed#appearance-and-controls).
- Read availability from `capability-matrix.json` and the mounted snapshot's
  `capabilities`, never from a plugin-local feature flag.
