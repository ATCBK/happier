title: Plugin quickstart
description: Create a visible plugin page with one Action, develop it, test it, and pack it.
---

Create a plugin, open its page in Happier, and invoke its first Action. The
default scaffold includes a declarative page and a **Save note** Action:
Happier renders the declared nodes without a bundler, a UI dependency tree, or
a build step before the page appears.

For every authoring command and the exact review-decision lifecycle, see the
[Plugin authoring CLI](/plugins/packaging/authoring-cli) reference.

> Release status: the author packages are not publicly installable yet. The
> empty-directory current-development-source flow and loaded development-stack
> proof are feature evidence, while package publication and post-publication
> installation are release-owned evidence. Source checks do not imply loaded
> platform proof, and neither one implies a published SDK release.

Authoring commands here use `hdev`, the development-lane CLI — that is the one
default path for plugin source development. The same `plugins` command surface
exists on the published `happier` CLI: use that lane to validate an installed
plugin against a published release, and expect published copies of the
examples to name `happier` instead.

## Create → dev → test → pack

```bash
hdev plugins create my-plugin
cd my-plugin
hdev plugins dev

# If dev stays attached, run the remaining commands in a second terminal
# rooted at my-plugin.
hdev plugins test .
hdev plugins pack .
```

`plugins create` derives the display name and a local plugin id from the
directory name. Use `--id com.example.my-plugin` when you need a durable
publisher-owned id.

If `plugins dev` returns an approval Artifact ID, review it in the Happier Inbox,
then run `plugins dev` again to continue watching. See
[pending reviews](/plugins/packaging/authoring-cli#review-a-pending-change).

After `plugins dev` registers the source, open the plugin's app page in Happier
and choose **Save note**. The page invokes the declared Action with
`{ note: 'hello' }`; its handler returns that note. Edit the greeting in
`src/ui/surfaces.ts` to see the development loop replace the page.

`plugins test .` runs the generated daemon-independent suite through Happier's
managed JavaScript runtime. It builds the module, loads its exported `manifest`
and `activate` through the public testkit, and invokes **Save note**. Start with
that passing contract and add your own behavior. `plugins pack .` writes an
npm-compatible `.tgz` and SHA-256 sidecar outside the plugin root; use the path
it prints. [Pack plugins](/plugins/packaging/pack) and
[Install and trust](/plugins/packaging/install-trust) cover distribution and
the separate authority decisions for installation.

### What to import from where

These are the imports used by the generated page, Action, and test. Check the
[generated public API inventory](/plugins/api/surface) for exact exports and the
[generated availability page](/plugins/manifest/availability) before adding a
contribution or service family. A `deferred` family is not supported for ordinary
author use; follow its recorded unblock condition.

| File you edit | Public import | Purpose |
| --- | --- | --- |
| `src/index.ts` | `definePlugin` from `@happier-dev/plugin-sdk` | Declare the plugin and its Action handler. |
| `src/ui/surfaces.ts` | `defineUiSurfaceDefinition` from `@happier-dev/plugin-sdk` | Declare the page and its Action button. |
| `src/index.ts` | `defineProtocolObject`, `defineProtocolString` from `@happier-dev/plugin-sdk/protocol` | Describe the closed Action input and result. |
| `test/index.test.mjs` | `createPluginTestkit`, `createPluginUiTestkit`, `createSurfaceContextFixture` from `@happier-dev/plugin-sdk/testing` | Invoke the Action and check the page declaration without a daemon. |

Use the [SDK entrypoint map](/plugins/api/sdk-entrypoints) when the plugin grows.
For an executable page, choose the [React Native scaffold](/plugins/ui/react-native)
or [hosted-web scaffold](/plugins/ui/hosted-web); hosted runtime availability is
reported per host. The [authoring CLI reference](/plugins/packaging/authoring-cli#create-and-develop)
also covers the `session-agent` template, which emits a distinct, import-safe
Session-runner leaf and takes no `--ui`.

`plugins dev` registers the exact trusted source with the daemon and may remain
attached for status output. The daemon owns observation, dependency
preparation, artifact compilation, candidate validation, and the per-plugin
swap. It imports the development module only as the activation entry and calls
its generated `activate(api)` export. The CLI does not keep a second watcher or
currentness model.

This normal create-to-dev loop prepares dependencies automatically. For package
aliases, dependency repair, registry selection, status, or manual reload, use
the [authoring CLI reference](/plugins/packaging/authoring-cli).
Copyable public patterns live in the maintained repository examples under
[`packages/plugin-sdk/examples/`](https://github.com/happier-dev/happier/tree/v0.3/packages/plugin-sdk/examples);
choose the smallest matching example. Any copy an installed SDK
may carry under `node_modules/` is a release-owned snapshot, not the maintained
source. This does not change the current prepublication hold.

For a custom Session Agent, that activation entry is not the runner entry. The
runner imports only the exact named factory leaf in the Agent's
`sessionRunnerFactory` locator; it never calls `activate`. Keep that leaf
separate and import-safe, because activation and runner execution can be
different realms with no shared process-global singleton.

The explicit local install or development command is the code-trust action for
that exact source, so it does not add a second trust prompt. Normal edits under
the approved source identity do not prompt. New declared authority or
credential access remains a separate user decision.

## Generated layout

```text
my-plugin/
  .agents/
    skills/
      happier-plugin-authoring/
        SKILL.md
  src/
    ui/
      surfaces.ts
    index.ts
  test/
    index.test.mjs
  package.json
  tsconfig.json
```

`.agents/skills/happier-plugin-authoring/SKILL.md` is a generated workflow
guide for the coding agent you author with, not an API reference. It is a real
source artifact: the scaffold's `files` inventory ships it alongside `dist`, so
it travels in the packed archive.

During development, `src/index.ts` is the authoring source of truth. Packing
evaluates that module once, validates the canonical projection, and writes
`.happier-plugin/plugin.json` into the archive. Installed and marketplace
discovery read that generated JSON without executing author code.

`hdev plugins create my-plugin --id com.example.my-plugin` generates exactly
this `src/index.ts`. It uses the code-defined authoring helper and exports the
ordinary named `manifest` and `activate` ABI:

```ts
import { definePlugin } from '@happier-dev/plugin-sdk';
import { defineProtocolObject, defineProtocolString } from '@happier-dev/plugin-sdk/protocol';

import { mainSurface } from './ui/surfaces.js';

export { mainSurface };

export const { manifest, activate } = definePlugin({
  id: "com.example.my-plugin",
  version: "0.1.0",
  displayName: "My plugin",
  description: "Local Happier plugin scaffold for My plugin.",
  runtime: { apiVersion: 1 },
  entrypoints: { daemon: './dist/index.js', development: './src/index.ts' },
  actions: {
    'save-note': {
      title: 'Save note',
      description: 'Returns the supplied note from one minimal plugin action.',
      surfaces: ['agent', 'cli', 'mcp', 'ui'],
      inputSchema: defineProtocolObject({
        note: defineProtocolString(),
      }, { policy: 'closed' }),
      resultSchema: defineProtocolObject({
        note: defineProtocolString(),
      }, { policy: 'closed' }),
      async run(input) {
        return { note: input.note };
      },
    },
  },
  ui: {
    surfaces: [mainSurface],
    translations: [{
      locale: 'en',
      messages: {
        'scaffold.main.title': "My plugin",
        'scaffold.main.greeting': "Hello from My plugin",
        'scaffold.action.saveNote': 'Save note',
      },
    }, {
      locale: 'fr',
      messages: {
        'scaffold.main.title': "My plugin",
        'scaffold.main.greeting': "Bonjour de My plugin",
        'scaffold.action.saveNote': 'Enregistrer la note',
      },
    }],
  },
});
```

Without `--id`, the id is derived from the directory name as
`local.my-plugin`. `src/ui/surfaces.ts` holds the one surface declaration this
entry re-exports; the default declarative renderer is projected from the
manifest, so nothing has to be built before it appears. Choosing
`--ui reactNative` instead adds the renderer's exact package export; `--ui hostedWeb`
adds a conventional `.happier-plugin/ui/hosted-web/<artifact-id>` directory. The
daemon-owned compiler consumes either shape without an author-owned build config.

The action id is local to the plugin. Happier owns its structured global
identity and renders it as `com.example.my-plugin/actions/save-note` only where
a global CLI, wire, or display boundary needs qualification.

## Related

- Add declarations and their handlers or runtimes to the matching
  `definePlugin(...)` family.
- Use `PluginInvocationContext.services` and `context.ui` inside invoked
  handlers.
- Choose the smallest [task guide](/plugins/guides): Agent mode, Provider,
  SCM, Voice, background service, or invocation service.
- For a feature-owned integration, use the
  [cross-plugin contribution guide](/plugins/guides/cross-plugin-contributions).
  Ordinary contributors import the feature protocol, derive role facts from an
  operation's `.declaration`, and bind their existing Action with `.bind()`;
  they do not create a generic protocol or scan Actions.
- Use native `AgentRuntime` factories only for custom executable Agents; the
  host retains session, turn, input, transcript, activity, persistence, and
  process lifecycle ownership.
- Choose React Native for trusted cross-platform plugin UI, hosted web for its
  isolated artifact source contract, or declarative settings/status/actions for
  UI rendered entirely by Happier. Hosted runtime availability is reported per host,
  so read it from the host rather than advertising it as a global capability.
